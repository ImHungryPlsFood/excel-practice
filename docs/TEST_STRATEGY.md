# CELLCRAFT 테스트 및 품질 검증 전략 (TEST_STRATEGY)

- **문서 버전:** 1.0.0
- **작성일자:** 2026-10-22
- **작성자:** 수석 QA 엔지니어 & 아키텍트
- **상태:** 확정 (Approved for Implementation)

---

## 1. 개요 및 테스트 피라미드

CELLCRAFT는 사용자가 직접 수식을 작성하고 셀을 조작하는 인터랙티브 교육 플랫폼이므로, 일반 웹사이트보다 훨씬 엄격한 계산 정확성과 상호작용 신뢰성이 요구된다.
테스트 계층은 **단위 테스트(Vitest) -> 속성 기반 테스트(fast-check) -> 통합 및 규칙 테스트 -> 브라우저 E2E 테스트(Playwright)**로 구성한다.

---

## 2. 세부 검증 전략 명세 (Q-01 ~ Q-09)

### [Q-01] Excel 대조 골든 테스트 (Excel Golden Test)
- **목적:** 수식 엔진 어댑터(HyperFormula GPLv3)의 계산 결과와 실제 Microsoft Excel 프로그램의 계산 결과가 셀 단위(`A1:Z100`)로 정확히 일치하는지 자동 대조한다.
- **테스트 환경 및 선행 조건 (사용자 결정 2026-10-22 반영):**
  - 기준 파일: `tests/fixtures/golden-excel-calculations.xlsx` (사용자가 MS Excel 정품에서 직접 작성 및 저장하여 제공).
  - **[Phase 2 착수 선행 조건]**: 본 기준 파일이 `tests/fixtures/` 디렉터리에 존재하지 않는 경우, Phase 2의 `CARD-02B`(수식 계산 엔진 어댑터) 작업 카드는 착수할 수 없으며 대기해야 한다.
  - 테스트 러너(`tests/unit/engine/golden-excel.test.ts`)는 SheetJS로 기준 파일의 사전 계산된 원본 캐시 값(`cell.v`)을 읽고, 동일한 수식(`cell.f`)을 CELLCRAFT 수식 엔진에 주입하여 재계산한 뒤 두 값을 비교한다.
  - 부동소수점 오차 허용치(Epsilon): `1e-9`.
  - **불일치 처리 원칙:** 불일치가 발생하면 테스트를 실패 처리하거나, 수학적/스펙상 정당한 차이인 경우 `docs/EXCEL_DIFFERENCES.md`에 사유(예: 1900년 윤년 버그 처리 방식, 부동소수점 반올림 규칙 차이)를 공식 기록한다.

### [Q-02] 데이터 교란 채점 (Perturbation-Based Scoring)
- **목적:** 원본 9.1절 요구사항을 완벽히 충족하여, "단순히 숫자를 직접 입력해 우연히 맞힌 경우", "범위를 잘못 지정한 경우", "상대/절대 참조 오류"를 정확히 감별한다.
- **채점 알고리즘:**
  1. **초기 상태 채점:** 기본 데이터셋에서 사용자의 셀 계산 결과가 기대값과 일치하는지 확인.
  2. **교란 데이터셋(Perturbed Datasets) 주입 (최소 3개 변형):**
     - 변형 A: 입력 데이터 셀에 난수 가산 (`+10`)
     - 변형 B: 데이터 행 추가 또는 비어 있는 행 삽입
     - 변형 C: 데이터 값의 크기 배율 변경 (`*2`)
  3. 사용자가 입력한 수식 객체를 교란된 시트에 적용하여 재계산 실행.
- **오답 판정 행렬 (Decision Matrix):**

| 사용자 입력 상태 | 기본 데이터 결과 | 교란 데이터 A 결과 | 교란 데이터 B 결과 | 판정 결과 (Diagnosis) | 사용자 피드백 문구 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 숫자를 직접 하드코딩 (예: `150`) | 일치 | 불일치 (변화 없음) | 불일치 (변화 없음) | **하드코딩 오류 (HARDCODED_VALUE)** | "수식 대신 계산된 값을 직접 입력하셨습니다. =SUM(...) 함수나 연산자를 사용해 수식을 작성해 보세요." |
| 올바른 수식 (`=SUM(B2:B6)`) | 일치 | 기대값과 일치 | 기대값과 일치 | **완전 정답 (PASS)** | "정확한 수식으로 문제를 완벽히 해결하셨습니다!" |
| 범위 누락 (`=SUM(B2:B5)`) | 불일치 | 불일치 | 불일치 | **범위 오류 (INCOMPLETE_RANGE)** | "합계 범위가 올바르지 않습니다. 마지막 행(B6)이 포함되었는지 확인하세요." |
| 절대참조 누락 후 복사 (`=B2*$D$1` 대신 `=B2*D1`) | 첫 셀 일치 | 복사된 셀 불일치 | 복사된 셀 불일치 | **참조 오류 (MISSING_ABSOLUTE_REF)** | "수식을 아래로 복사할 때 할인율 셀($D$1)이 변경되지 않도록 F4 키를 눌러 절대 참조로 고정해야 합니다." |

### [Q-03] 콘텐츠 자체 검증 파이프라인 (Content Self-Validation)
- 모든 학습 모듈 및 문제는 Zod 스키마(`ProblemSchema`)를 통한 정적 유효성 검사를 통과해야만 빌드에 포함된다.
- **CI 검증 러너 (`scripts/verify-content.ts`):**
  - 각 문제 정의에는 반드시 **기준 정답(Canonical Solution)**과 최소 2개 이상의 **대표 오답(Common Misconceptions)** 데이터가 포함되어야 한다.
  - CI 파이프라인 실행 시, 모든 문제에 대해:
    1. 기준 정답 주입 -> 채점 통과(`PASS`) 확인.
    2. 대표 오답 A 주입 -> 예상된 에러 코드(`HARDCODED_VALUE` 등)로 정확히 실패하는지 확인.
    3. 대표 오답 B 주입 -> 예상된 에러 코드(`INCOMPLETE_RANGE` 등)로 정확히 실패하는지 확인.
  - 단 1개의 문제라도 위 조건을 만족하지 못하면 빌드가 중단된다.

### [Q-04] 속성 기반 테스트 (Property-Based Testing with fast-check)
- 임의로 생성된 수만 가지 무작위 입력을 통해 엔진의 불변식(Invariant)을 검증한다:
  - **Undo/Redo 왕복 불변성:** 임의의 50회 셀 편집 및 서식 변경 후 `Undo`를 50회 실행하면 초기 상태 해시와 100% 동일해야 함.
  - **자동 채우기(Autofill) 수식 참조 변환:** 아래로 $N$행 드래그 시 상대 행 참조는 정확히 $+N$ 증가하고, 절대 참조(`$`)는 보존되어야 함.
  - **F4 참조 전환 순환성:** A1 -> \$A\$1 -> A\$1 -> \$A1 -> A1의 4단계 토글이 무작위 셀 주소에 대해 무한히 순환 유지되어야 함.

### [Q-05] 한글 입력기 (IME) 및 다국어 조합 처리
- **문제점:** 한글은 자음과 모음이 결합하는 조합형 문자이므로, 조합 중(`isComposing === true`) `Enter` 키를 누르면 글자 조합 확정과 셀 편집 종료 이벤트가 동시에 발생하여 오작동(마지막 글자 중복 입력 또는 원치 않는 튜토리얼 스텝 스킵)이 발생함.
- **대응 로직:**
  - `compositionstart`, `compositionend` 이벤트 리스너를 셀 에디터에 등록.
  - `onKeyDown` 핸들러에서 `event.nativeEvent.isComposing`이 참일 경우 셀 커밋(`commit`)을 지연하고 조합만 완료시킴.
- **검증:** Playwright E2E 테스트에서 한글 단어(예: `"합계"`, `"홍길동"`) 입력 및 `Enter` 누름 시 글자 깨짐 및 단계 조기 종료가 발생하지 않음을 필수 검증.

### [Q-06] 브라우저 단축키 충돌 방지 및 대체 안내
- 웹 브라우저가 시스템 차원에서 가로채는 단축키 목록을 정의하고 처리 방침을 확정한다:
  - `Ctrl + N` (새 창) -> 웹에서 차단 불가. 앱 내에서는 셀/시트 신규 생성 단축키로 쓰지 않음.
  - `Ctrl + W` (탭 닫기) -> 웹에서 차단 불가.
  - `F1` (도움말) -> 브라우저 도움말이 열리므로 `e.preventDefault()` 적용.
  - `F4` (절대참조 토글 / 작업 반복) -> 브라우저 단축키와 충돌하지 않으므로 완벽 지원.
  - `Ctrl + Z`, `Ctrl + Y` (실행 취소 / 다시 실행) -> 브라우저 기본 히스토리를 차단하고 자체 Undo/Redo 스택과 연결.
- 대체할 수 없는 단축키는 학습 화면 우측 정보 패널에 "웹 브라우저 환경 안내: 본 단축키는 브라우저 정책상 버튼 클릭으로 대체됩니다"라고 투명하게 표시.

### [Q-07] 날짜 일련번호 및 한국 로케일(Locale) 정밀 테스트
- **1900년 윤년 처리:** Microsoft Excel의 역사적 버그(1900년을 윤년으로 간주하여 1900-02-29를 일련번호 60으로 부여)와 엔진 어댑터 간의 날짜 변환 계산식을 명시적으로 테스트.
- **날짜 일련번호 기준:** 1900년 1월 1일 = 1 기준 호환성 테스트.
- **한국 로케일 서식:** `YYYY"년" MM"월" DD"일"`, `₩#,##0` 통화 서식 파싱 및 포맷팅 테스트.

### [Q-08] CI 품질 게이트 (Automated Quality Gate)
GitHub Actions 또는 CI 파이프라인에서 다음 단계를 단일 파이프라인으로 순차 실행하며, 하나라도 실패하면 병합(Merge)을 차단한다:
1. `npm run typecheck` (`tsc --noEmit`, strict 모드)
2. `npm run lint` (ESLint: `no-eval`, `no-new-func`, `react/no-danger` 위반 검사)
3. `npm run format:check` (Prettier 포맷팅 검사)
4. `npm run test:unit` (Vitest 단위 테스트 및 콘텐츠 스키마 검증)
5. `npm run test:rules` (Firebase Local Emulator Firestore 보안 규칙 테스트)
6. `npm run build` (Vite 프로덕션 빌드 성공 여부 검사)
7. `npm run test:e2e` (Playwright 브라우저 E2E 테스트)

### [Q-09] React 오류 경계(Error Boundary) 및 저장 실패 복구 UX
- **오류 격리:** 스프레드시트 컴포넌트, 튜토리얼 Spotlight, 사이드바를 각각 독립된 `<ErrorBoundary>`로 감싼다. 수식 엔진이 알 수 없는 예외를 던지더라도 전체 페이지가 하얗게 죽지 않고 그리드 영역에 "수식 계산 중 문제가 발생했습니다. [이전 안전 상태로 되돌리기]" 버튼을 노출한다.
- **저장 재시도 및 오프라인 캐시:**
  - 네트워크 단절 시 학습 진행도를 브라우저 `localStorage` / `IndexedDB`에 임시 저장.
  - Firestore 쓰기 실패 시 지수 백오프(Exponential Backoff: 1s, 2s, 4s, 8s)로 최대 3회 자동 재시도.
  - 최종 저장 실패 시 화면 상단에 붉은색 토스트 알림 표시: *"네트워크 연결이 불안정하여 진도가 서버에 저장되지 않았습니다. 인터넷 연결을 확인해 주세요. 로컬에 안전하게 보관 중입니다."*
